# 作答事件、反馈与月度记录

处理学生增多、重复测验和月度汇总时使用。不要求先安装数据库或搬动已有工程；用现有JSON、Markdown及文件目录也能建立关联。只加载本批及相关目标记录，不把所有学生历史塞进对话。

## 题目和作答分开

| 对象 | 保存什么 |
| --- | --- |
| 题目 | 稳定question_id、题干与图、原题号、来源及实际核读范围、题目版本 |
| 作答 | 独立attempt_id、student_id、question_id与版本、实际作答日期、原答文件及页码、批改、完整性与提示情况 |
| 目标 | target_id、所据attempt_id及具体证据、已完成部分、首次偏离、待验证原因、通过所需动作 |
| 练习与复测 | 稳定题号到目标及原作答的映射、题源关系、已提供的帮助、每次真实提交与核对 |
| 反馈与交付 | 接收人、正文版本、支持评价的证据、建议与已确认安排、有效文件及核验结果 |

同一道题可有多次作答；相似题查重只处理题库，不能合并掉孩子再次出错或后来改正的事件。改题干须保留版本，旧作答继续指向当时题面。原照片与批改留原件，转录和更正另存。

用户只说“第3题错了”时，先定位练习版本，再按题号映射到原目标。没有提到的题保持未报告，不能默认全对；“全对”先记自述，是否独立及关键步骤仍依材料核对。复测结果不得反写成原测失误的确定原因。

同一份作答换格式、发了两个渠道或补发同一页时，关联到原作答记录。实际重做或看过解析之后订正时，再记一条事件，附原作答 ID 和当时获得的帮助。仅凭文件名变化无法判断是否真的重做。

## 两类状态分别记

材料流程记录：已生成、实际布置、实际提交、完成核对及各自日期。未知日期留空。材料生成后既可以尚未布置，也可以已布置待交，不能只用一个“待复测”抹平区别。

目标表现记录：证据待核对／原因待验证、提示后完成、核心步骤通过、达到本轮要求、延后保持、仍需巩固。收到新作答才更新相应结论，保留依据、独立性及历史状态变化；与旧系统状态名不一致时做映射，不擅自改写历史记录。

不能因为创建PDF就更新能力状态，也不能靠两次自报全对宣布永久掌握。一个额外难点失败不自动推翻已独立通过的基本动作；同一错误再次出现则重新检查目标与前置条件。

按题保存最终答案、目标步骤的表现、使用的帮助及独立性依据。缺一项就按事实留空。帮助情况可写孩子自述独立、已知获得的提示、已看过解析或待确认。已看到答案后的订正可用于检验是否会解释。独立新题中目标步骤和适当变式均有证据之后，再按[复测规则](retest-and-delivery.md)记录初步通过。

## 月度汇总

先依据实际作答日期选当月记录，整理日期另记；未知日期归待确认，跨月遗留问题单列。按目标归并训练、保留每次作答证据。默认所有确定错题有索引，重点原题完整展开；用户要全部纸质原题时加附录。学生册继续用原错题、简短要点和同类练习，教师端才出现内部代码和状态表。

区分不同题数量、作答次数、复发次数和目标数量；多错因标签可能重叠，不能相加作总题数。只收错题或题目条件不同时，不计算整体错误率或承诺提分。向家长说明本月具体问题与有证据的变化，不把“未交”写成“退步”。

## 能力不足时

先维护当前批次清单和关键证据，索引可后续补建；不声称已经部署检索、长期记忆或自动采集系统。已有稳定档案无须强行迁移。示意结构见[学习记录示例](../assets/learning-record.example.json)，其中所有人物、日期、题目及事件均为虚构。
